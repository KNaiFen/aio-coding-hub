# 可配置模型路由与最终模型计价

## Goal

允许用户按客户端模型名，在全局或单个供应商范围覆盖最终出站模型和思考强度，并让费用、用量账本和额度门控使用最终出站模型。

## Requirements

- 全局规则对 Claude、Codex、Grok、Gemini 共用；供应商可继承、整套覆盖或明确禁用。
- 原模型去除首尾空格后区分大小写精确匹配；不支持通配符、默认规则或链式改写。
- 目标模型与思考强度可独立覆盖，均为空的规则无效；思考强度使用自由文本。
- 覆盖普通推理与 Codex Responses Compact，不修改模型列表、探测、Token 计数等辅助请求。
- 每个供应商尝试从同一请求基线重新计算；新规则在协议桥接和旧映射后最终覆盖；`aio/` 托管模型不参与。
- 任何运行时解析、未来请求形状或审计失败都保留原请求继续转发，不影响熔断。
- 最终成功供应商的最终出站模型是唯一计价依据；缺价显示未定价，不回退原模型价格。
- 首页、日志、进行中卡片和 TUI 显示原模型到最终模型、思考强度与规则来源。

## Acceptance Criteria

- [ ] 全局和供应商策略可保存、读取、复制、分享和导入导出，旧数据兼容。
- [ ] 四类 CLI 在支持的推理路径按规则改写；空值、未命中、辅助请求和托管模型保持不变。
- [ ] A 供应商失败后 B 供应商按客户端原模型重新匹配，不继承 A 的结果。
- [ ] 计价、账本、成本补填与供应商额度累计使用最终模型；缺价费用为空。
- [ ] 桌面和 TUI 能稳定展示路由，损坏审计 JSON 只隐藏标记。

## Constraints

- 全局策略默认关闭且为空。
- 最多 128 条规则；模型名最多 256 字节，思考强度最多 64 字符；拒绝控制字符和重复源模型。
- 不新增错误码，不在本机运行任何 Rust 工具。
