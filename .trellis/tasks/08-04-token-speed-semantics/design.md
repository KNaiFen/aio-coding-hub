# Token 速度口径设计

## 决策

- `ttfb_ms` 继续表示最终成功上游尝试内的首字节时间，用于供应商性能，不参与新的 Token/s 分母。
- 记录版本化的上游生成时序：版本 1 的 `upstream_stream_duration_ms` 表示最终被采用上游流在网关接收侧首个到最后一个有效增量之间的毫秒数。
- 单请求 Token/s 和聚合都只在版本 1、输出 Token 大于零且上游生成时长大于零时计算：`output_tokens / (upstream_stream_duration_ms / 1000)`。
- 未携带版本 1 时序的历史记录显示 `—`，聚合 SQL 排除该行；不回退到混合时间原点的旧公式。
- 非流式、单个有效增量、未完整采集或被下游背压污染的响应保持版本 0，显式没有可比 Token/s。

## 数据流

1. 流内重试前缀检查在原始上游协议上记录有效增量；未被采用的失败尝试连同其计时状态一起丢弃。
2. 最终流提交后，由协议桥之前的独立有界中继持续读取原始上游 SSE，并补记后续有效增量。若中继队列填满，说明后续时间会受消费侧节奏影响，本次计时立即失效。
3. 请求结束路径将首尾间隔和版本写入请求日志及使用台账。
4. AIO、实时事件、TUI 和聚合读取同一个版本化字段，仅展示有效生成阶段速率。

## 边界

- 首个上游字节但尚未包含有效输出增量时不开始生成计时。
- 重试前各尝试、回退等待和供应商切换不计入最终成功流的 Token/s。
- 协议桥、响应修复、插件和下游发送都位于计时器之后，不得重定义供应商生成区间。
- 流内错误、计时污染、无输出 Token 或只有单个有效增量时不产生 Token/s。
