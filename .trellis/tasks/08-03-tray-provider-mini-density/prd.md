# 稳定 Tray 供应商小窗布局

## Goal

在保留 `0.60.45` 已交付的 24px 行密度基础上，收紧 Tray 供应商 mini 面板宽度，并让名称、18 格状态条、成功标签与失败标签在任何计数长度下保持固定对齐。

## Reopened Evidence

- `0.60.45` 已将前端行高、滚动上限和原生窗口高度同步为 24px/240px。
- 用户在 2026-08-03 提供的实际运行截图显示：`440px` 面板仍为名称区保留过多空间，而 `64px` 合计区在四位成功数下发生换行。
- 截图中的 `成1034`、`败33` 被拆成标签与数字两行，导致“成”“败”的位置和其他供应商行不一致，因此首轮实现不满足稳定横向布局验收。

## Requirements

- 保留每行 24px、最多十行、240px 滚动上限和 0/1/5/10/20 行既有高度公式。
- 原生窗口逻辑宽度从 440px 收紧到 404px；扣除左右边框后，前端行内容使用固定 96px 名称区、178px 状态区和 88px 合计区。
- 名称超过固定区域后单行省略，`title` 保留完整名称；原因标记、去重规则和颜色语义不变。
- 合计区使用固定的 `成 / 成功数 / 败 / 失败数` 四列。标签不随数字移动，数值右对齐、使用 tabular numbers 且不得换行。
- 五位以内计数显示完整数字；更大值使用确定性的中文紧凑单位，`title` 和无障碍名称继续保留精确计数。
- 标题栏、圆角、毛玻璃、空状态、悬停关闭、快照冻结、滚动回顶、供应商筛选排序与计数口径不变。

## Acceptance Criteria

- [ ] 面板逻辑宽度为 404px，标题和列表无横向溢出，较 440px 版本不再保留无意义的名称区空白。
- [ ] 短名称、超长中英文名称及一至三个原因标记混排时，名称区始终为 96px；超长名称省略且可查看完整标题。
- [ ] 18 格状态条始终占 178px，精确容纳 18 个 8px 状态格和 17 个 2px 间距，不会被名称或计数挤压。
- [ ] `成`、成功数、`败`、失败数分别固定在 12/32/12/32px 轨道；0、一位、四位、五位和 `u32` 级计数均不换行、不推动标签。
- [ ] 1/5/10/20 个供应商的高度、十行滚动上限、滚动回顶、悬停交接和空状态保持既有行为。
- [ ] React 契约测试覆盖列宽、长名称、计数边界与精确无障碍值；原生宽度/placement/2x 缩放测试由 GitHub Actions 通过。
- [ ] 404px 普通像素密度和 2x fixture 截图均无重叠、换行、裁切或错位。
- [ ] 功能 PR、精确 main SHA 候选 CI 与 `aio-coding-hub-v0.60.46` Release 验证完成后才可归档。
