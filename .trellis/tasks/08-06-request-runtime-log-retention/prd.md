# AUD-056 请求日志与运行日志留存

## Goal

为原始请求明细和应用运行日志建立默认 7 天留存与可观察的空间治理，同时永久保留用量账本和聚合统计。

## Requirements

- 请求日志默认 7 天；历史 `0=永久` 配置通过版本化迁移自动变为 7 天。
- `usage_ledger` 与统计聚合永久保留，上月用量、Token、成本、趋势和排行榜不受明细清理影响。
- 到期后只删除原始请求明细、错误详情和重试链。
- 运行日志默认 7 天，增加 256 MiB 软上限；只从最旧的已关闭日滚动文件回收。
- 设置页允许调整请求日志与运行日志天数，但不再提供永久选项。
- 清理后展示 SQLite 可回收空间；不自动 VACUUM，显式压缩仍由用户触发。

## Acceptance Criteria

- [ ] 新安装默认 7 天，旧 schema 的 0 持久迁移为 7，所有写入边界拒绝 0。
- [ ] 请求明细到期删除前仍完成 ledger 覆盖校验，统计查询保持完整。
- [ ] 运行日志按日龄和容量清理，活动文件永不删除，仅活动文件超限时保守保留并记录。
- [ ] 清空请求日志不会自动缩小 DB，UI 显示可回收字节，手动压缩后空间才归还。
- [ ] 前端、IPC、settings migration、runtime cleanup 与云端 bindings/test 全部一致。
