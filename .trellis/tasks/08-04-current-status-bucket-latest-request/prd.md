# 当前状态格按最新请求着色

## Goal

让供应商状态条的最后一个当前时间格反映此刻最新可用状态，而历史格继续表达整个时间段的成功率。

## Requirements

- 仅代表当前对齐时间段的最后一个显示格采用该时间段最新请求结果：最新请求成功为绿，失败为红，无请求为灰。AIO 的三个 10 分钟格继续与一个 30 分钟 TUI 时间段对齐，最后显示格读取整个当前 30 分钟段的最新结果。
- 格子滚入历史后恢复现有成功比例规则；当前阈值和历史计数不变。
- AIO 与 TUI 必须一致；共享该时间线的托盘迷你状态条也应自然获得同一语义。
- 继续使用现有“真实上游终态请求”成功/失败分类；手动测试、本地失败、跳过尝试和取消请求不产生可用性事实。
- 同一 trace 同一供应商的重试继续按最终成功优先，不把一次逻辑请求拆成互相覆盖的 attempt。
- 同毫秒请求必须有确定性顺序，不能依赖 SQLite 未指定的同行顺序。

## Acceptance Criteria

- [ ] 当前格覆盖“先成功后失败为红”“先失败后成功为绿”“无请求为灰”。
- [ ] 上一格及更早格仍按现有 75% 成功率阈值着色。
- [ ] 12 格、18 格和 36 格消费者最后一格语义一致，历史边界保持对齐。
- [ ] 同毫秒结果有稳定、经过测试的最后请求判定。
- [ ] 失败分类、重试成功优先、failover 供应商归属没有回归。

## Engineering Decision

- “最后一条”按 `(observed_at_ms, rowid)` 升序后的末条观测确定。该表是普通 SQLite rowid 表，`rowid` 代表观测首次插入顺序；同一 trace/provider 的 UPSERT 保留原 rowid。
