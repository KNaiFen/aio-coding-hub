# TUI 信息密度与托盘悬浮面板优化发布

## Goal

在一个补丁版本中完成三项相互独立但都面向日常观测效率的交付：精简独立 TUI 摘要并使用本地时区；归档已完成的 PENDING 历史；精修 macOS 顶栏供应商悬浮面板的信息密度和系统观感。

## Requirements

- 子任务 `08-02-tui-summary-local-time` 负责独立 TUI 顶部摘要与供应商详情时间显示。
- 子任务 `08-02-pending-completed-archive` 负责把已完成条目移出活跃 PENDING 上下文，同时保留完整历史和发布证据。
- 子任务 `08-02-macos-tray-mini-polish` 负责 18 格状态条、成功/失败汇总、紧凑供应商行和 macOS 原生圆角悬浮窗。
- 三个子任务必须在同一短期分支内保持可独立审查，不扩大到余额刷新、路由、熔断、观测采集口径或其他界面重做。
- 本地只运行 Node、TypeScript、前端测试、前端构建和非原生静态检查；所有 Rust、Cargo、绑定生成和原生打包由 GitHub Actions 完成。
- 通过 `origin` 的 PR 合并到 `main`，按默认补丁策略从 `0.60.43` 升级到 `0.60.44` 并发布正式 Release。

## Acceptance Criteria

- [ ] 三个子任务各自满足 PRD 验收标准，且父任务完成跨子任务差异审查。
- [ ] `PENDING.md` 不再加载已完成的 11 个长条目，但完整历史可以从明确链接的归档文件访问。
- [ ] TUI 请求/供应商视图共享同一摘要，供应商详情时间按系统时区显示。
- [ ] macOS 悬浮面板显示 18 个扁长状态格、每家供应商的总成功/失败数，并具有圆角原生 Popover 观感。
- [ ] 前端测试、类型检查、lint 和 Vite 构建通过；云端完整 CI、macOS 集成构建和发布工作流通过。
- [ ] `aio-coding-hub-v0.60.44` 正式发布，Release 资产和 `SHA256SUMS.txt` 完整且校验一致。

## Notes

- 父任务只拥有需求映射、集成审查和发布证据；具体代码由三个子任务承接。
