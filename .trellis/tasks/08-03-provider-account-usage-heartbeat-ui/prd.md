# 稳定账户余额心跳渲染

## Goal

让五秒消费者心跳保持为不可见的内部保活，只在首次加载和用户手动刷新时提供加载反馈，消除 Providers 页周期性闪烁和布局抖动。

## Requirements

- 保留 `useProviderAccountUsageQuery` 的五秒间隔、后台轮询、查询键和后端 force 协议。
- 首次没有查询结果时可显示“账户: 刷新中”；已有结果后的后台心跳不得替换摘要、清空指标、旋转图标或禁用按钮。
- 手动刷新期间保留当前摘要和指标，仅旋转固定尺寸图标并阻止重复点击。
- 手动或后台请求完成后按真实结果更新；失败、过期或无有效金额时继续隐藏旧余额。
- 不处理无法稳定复现的批量余额获取事故，不改变 TUI、路由、熔断或后端调度。

## Acceptance Criteria

- [ ] 首次加载、首次失败和真实失败状态保持现有文案与颜色语义。
- [ ] 两张以上供应商卡经历至少三个五秒心跳周期时，余额文本、指标 DOM、按钮尺寸状态和卡片结构保持稳定。
- [ ] 后台成功完成后原位更新结果；后台失败完成后显示错误并隐藏旧指标。
- [ ] 手动刷新期间旧内容保持可见，图标旋转、按钮禁用，重复点击不产生并发 force 请求。
- [ ] 手动成功和失败均在完成后切换到真实结果，既有查询竞态与隔离测试保持通过。
