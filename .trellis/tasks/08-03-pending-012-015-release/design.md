# 集成与发布设计

## 任务边界

三个子任务不共享产品状态：TUI 子任务只格式化只读投影，余额子任务只修正 React 渲染状态，Tray 子任务只调整 mini 窗口的 CSS、计数表现与原生窗口几何。父任务只拥有集成审查、版本提升、发布和证据归档。

012/014 已在 `0.60.45` 形成闭环，可以独立归档。015 保持活跃：`0.60.45` 是其 24px 高度基础，不是最终完成证据；用户截图成为续作验收输入。

## Git 与 CI

- 012/014 的功能提交和 `0.60.45` 发布证据保持不变。
- 015 续作使用 `codex/tray-provider-mini-layout-followup`，只包含 Tray 横向布局、合同、测试和必要计划状态更新。
- 功能 PR CI 负责 Rust 格式、生成绑定、Clippy、Rust 测试、审计和原生编译；只应用与本任务直接相关的 cloud-native-fixes 补丁。
- 功能合并后从最新 `origin/main` 创建 `codex/release-0.60.46`，同步五个版本清单。Cargo.lock 版本漂移继续由 CI 生成。
- 版本 PR 的 main 合并 SHA 必须完成带 release-candidate 的成功 CI，随后才创建注释标签并运行 release workflow。
- 发布后另建归档 PR，避免在 Release 标签中提前声称 015 已完成。

## 视觉与回归门禁

前端 fixture 必须覆盖用户截图中的四位计数，以及短/长名称、零计数、五位数和超大计数；404px 普通与 2x 截图均需确认标签固定、数值不换行、18 格状态条不被挤压。原生 placement 和桌面制品仍由 macOS GitHub Actions 验证。

## 失败处理

任何 015 验收、候选制品或资产校验失败都阻止 `0.60.46` 发布与任务归档。若 404px 固定分配在视觉 fixture 中不可用，回到 015 设计文件调整固定列参数并保留总宽稳定；不得用可伸展名称列或计数换行规避。标签自动工作流若仅命中已知本地标签 clobber 问题，则从 `main` 对同一已解析标签执行 `workflow_dispatch`，不重写标签。
