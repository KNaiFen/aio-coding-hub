# 技术设计：AIO 本地观测服务与 SSH TUI

## 边界

桌面 AIO 负责生成只读观测快照；独立 `aio-tui` 只消费该快照并渲染终端。TUI 不读取数据库、不调用网关端口，也不会启动桌面程序。观测服务只绑定 `127.0.0.1:0`，启动后将端口和随机 Bearer Token 原子写入 `~/.aio-coding-hub/observer-v1.json`。Unix 文件权限为 `0600`，退出时仅删除 Token/PID 与当前实例一致的描述文件。

## 协议

协议版本为 v1。所有请求使用 Bearer Token，只有以下 GET 资源：

- `/api/observer/v1/health`
- `/api/observer/v1/snapshot?cli=<scope>&history_limit=0..50`

快照拥有单一共享 Rust DTO：元数据、各分区可用性、网关状态、首选供应商、最近模型推理请求、近十次主导供应商、全局推理并发、全局今日使用量、活动请求和终态请求。请求条目是脱敏投影，并包含详情页需要的路由尝试、Token、费用、耗时、Session、目录与压缩标记。认证、无效查询、版本不匹配和内部错误均使用固定结构与不含内部细节的错误消息。

## 数据与隔离

活动请求、熔断状态从进程内 GatewayRuntime 读取；路由/供应商、日志、用量和目录从独立只读 SQLite 访问读取。DB 查询有短超时、低并发限制和短缓存；单一分区失败返回不可用标志，不阻止其他分区。

新增 CircuitBreaker 的只读 peek。它按当前时间计算实际门禁结果（过期 OPEN 逻辑上可作为 HALF_OPEN 候选），但绝不修改内存、落库或发布事件。首选供应商为活动路由中第一个启用、未 OPEN 且未冷却的普通候选，不引入 Session 亲和或模型/账户配额猜测。

状态栏的最近/近十次只选模型推理终态日志；近十次按每条记录的最终实际供应商统计，平局取最近记录。全局并发复用现有活跃模型推理判定。今日 Token 和费用复用 usage ledger 的现有全局统计口径。

## 终端交互

`aio-tui` 默认运行 `logs`，`status` 持续原位重绘，`status --once` 适配管道。持续模式活跃时每 500ms 拉取，空闲和离线时每 2 秒拉取。离线显示陈旧快照并重读描述文件重连。

日志面板以 32 列为关键窄屏，单条五行：状态/时间、CLI/模型、目录/供应商、路由/耗时、Token/费用。活动项置顶；终态项最多 50 条。按键为滚动、翻页、跳首尾、刷新、切换 CLI、详情、返回、帮助和退出。终端初始化、panic 及退出必须恢复 raw mode、备用屏幕和光标。

## 分发

新增 Cargo workspace 内的协议 crate 和 `aio-tui` crate，桌面包保持默认成员。Release workflow 在既有四平台矩阵中单独构建并打包 TUI，附加到 Release 和 `SHA256SUMS.txt`，不进入 `latest.json` 或桌面安装包。TUI 与桌面 AIO 共享发布版本，并在协议版本不兼容时清晰提示升级。
