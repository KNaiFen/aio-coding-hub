# AIO 本地观测服务与 SSH TUI

## 目标

让通过 SSH 使用 Codex CLI 的用户在同一台运行 AIO 的主机上，能以独立终端界面查看实时路由、请求记录、并发和当天用量，而不依赖桌面 GUI。

## 需求

- AIO 运行时自动提供只读、本地回环的观测接口；接口或 TUI 的故障不得影响网关转发、重试、供应商健康或请求日志写入。
- 提供独立 `aio-tui` 可执行文件，支持 Windows x64、macOS Intel、macOS Apple Silicon 和 Linux x64。
- 默认命令进入可滚动的最近请求面板；`status` 显示持续更新的一行状态栏，窄终端可按字段换行；`status --once` 输出一次文本后退出。
- 支持 `--cli claude|codex|grok|gemini|all`，默认 `codex`。全局模式的状态栏首选供应商使用最近终态推理请求所属 CLI。
- 状态栏显示：排除熔断/冷却后的最高优先级供应商、上次模型推理请求的状态/重试/供应商、近十次请求主导供应商、全局模型推理并发、全局今日费用、全局今日输入/输出/缓存总 Token。
- 最近请求面板复用首页的语义：活动请求置顶且不占最近 50 条终态记录名额，支持滚动与详情；窄屏采用五行实用布局。
- 上次请求和近十次主导供应商只统计模型推理请求，保留失败与中断，排除辅助请求。最近请求面板保留首页范围内的全部代理请求。
- 观测数据不得包含正文、密钥、上游 URL、原始错误 JSON 或其他敏感配置。
- 本地不运行 Rust/Cargo/rustfmt/Clippy/Tauri 原生构建；Rust 验证和全平台构建仅在云端 CI 运行。

## 验收标准

- AIO 的请求转发在观测服务关闭、接口认证失败、SQLite 暂时不可读和 TUI 解析错误时行为不变。
- `aio-tui status` 持续显示所有约定字段；`aio-tui logs` 显示活动记录与 50 条最近终态记录，可切换 CLI、滚动和查看详情。
- 三个父请求与十个子代理活跃时并发显示 13；两个子代理结束后显示 11。
- 首选供应商遵循当前活动路由普通顺序，并跳过仍然 OPEN 或冷却中的供应商；读取状态不产生熔断状态迁移或持久化写入。
- 离线时 TUI 保留最后成功快照并每两秒重连，不自动启动 AIO。
- 发布版本包含四个平台的独立 TUI 制品和 SHA-256 校验和，不影响桌面更新器清单。

## 约束

- 不新增数据库迁移、用户设置、远程监听能力或 Tauri IPC 公共命令。
- 不拆分 SQLite 数据库，不改变请求日志保留和用量账本口径。
- 版本遵循补丁递增；本次实施时预计从 `0.60.38` 升至 `0.60.39`。
