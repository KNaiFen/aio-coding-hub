# TUI 请求卡模型路由分行

## Goal

当配置模型路由实际改变模型时，在独立 TUI 请求列表卡中用稳定的两行布局展示源模型和实际目标模型，避免窄终端截断掉路由结果。

## Requirements

- 仅当 `model_applied && source_model != effective_model` 时拆为两行。
- 第一行格式为 `CLI / 源模型 →`；第二行在卡片可用宽度内右对齐显示目标模型、可选 `·reasoning_effort` 与上下文压缩标记。
- 请求卡上的已应用思考强度不显示“思考”二字；模型未变化时仍使用单行模型信息。
- 普通请求卡保持五个内容行，路由请求卡为六个内容行，二者都另带现有分隔线。
- 每行必须使用 grapheme/Unicode 显示宽度截断；宽度为 0 或极小时不 panic、不负填充、不溢出，并尽量保留 CLI 起始与箭头。
- Statusline、详情页、Observer 协议、模型选择与网关路由不变。

## Acceptance Criteria

- [x] 宽度足够时精确显示源行和右对齐目标行，目标可显示 `·high` 与压缩标记。
- [x] 仅思考强度变化及普通请求仍为单行模型信息。
- [x] 0、1、极窄宽度、CJK 和超长模型名的每行显示宽度都不超过可用宽度。
- [x] 路由卡与普通卡混排时，状态、两个模型行、供应商、路由、指标和分隔线保持语义配色，选中和滚动正常。
- [x] Statusline 和详情页继续显示现有单行 `source→effective·思考high` 表示。
