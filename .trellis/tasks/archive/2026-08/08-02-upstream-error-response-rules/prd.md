# 上游错误响应规则

## Goal

在 CLI 管理页提供可配置的上游错误响应规则，让用户按原始上游 HTTP
状态码和错误正文关键词改写最终返回客户端的状态码或错误信息，同时保证
这一附加能力不会改变网关的转发、重试、熔断和供应商健康行为。

## Requirements

- 在“熔断与重试”下方提供规则列表、启停、新建、编辑和删除操作。
- 规则支持名称、说明、优先级、CLI/供应商范围、状态码条件、关键词条件及
  Any/All 组合方式；关键词采用大小写不敏感的字面子串匹配。
- 状态码与消息分别支持透传或自定义。透传消息需要提取上游错误信息并包装
  为 Claude、Codex/Grok 或 Gemini 客户端兼容的 JSON 错误信封。
- 只在最终 HTTP 4xx/5xx 响应上生效；HTTP 200 内嵌错误、网络错误、先失败
  后成功的中间尝试均不改写。
- 匹配和改写必须在重试、切换、熔断和健康计数完成后进行，所有这些机制继续
  使用真实上游状态。
- 任意配置、匹配、正文读取或响应构造异常都必须退回 AIO 原有响应；不能让
  规则功能阻止请求、改变供应商选择或导致网关崩溃。
- 首页和请求日志显示客户端最终状态，并显示命中规则徽标；尝试链保留原始
  上游状态。审计中不得保存正文、匹配关键词或错误消息。
- 规则使用现有设置文件持久化，不新增数据库；损坏或未来格式的规则逐条忽略。
- 始终保留现有请求日志与用量统计，不增加“跳过监控”选项。

## Acceptance Criteria

- [ ] 空规则配置与升级前行为完全一致。
- [ ] Any/All、优先级、CLI/供应商范围及四种状态/消息行为组合均有覆盖。
- [ ] 最终规则命中生成正确的三类客户端协议错误信封和 400–599 状态码。
- [ ] 先失败后成功、后续供应商失败、网络错误和 HTTP 200 内嵌错误不会误用
      早先规则结果。
- [ ] 重试次数、供应商切换、熔断计数、健康状态和尝试日志与未启用规则时一致。
- [ ] 损坏设置、超限正文、未知内容编码、畸形 JSON 及内部错误均安全退化。
- [ ] 首页与日志页徽标显示规则名、供应商及状态前后变化，损坏审计 JSON 只
      隐藏徽标而不影响列表渲染。
- [ ] 本地 TypeScript、前端单测、Lint 和 Vite 构建通过；Rust、生成绑定、
      rustfmt、测试和 Clippy 由 GitHub Actions 验证。
- [ ] PR CI 全绿后以普通 merge commit 合入 `main`，不升级版本或发布。
