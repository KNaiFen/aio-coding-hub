# TUI 请求日志显示思考强度

## Goal

让 TUI 请求日志中的每条 Codex 模型记录都能直接看出请求思考强度；发生模型路由时，同时看出源模型/请求强度和目标模型/有效强度。

## Requirements

- 非路由请求显示为 `Codex / <model>-<effort>`，例如 `Codex / gpt-5.6-terra-max`。
- 模型路由请求维持两行布局：第一行 `Codex / <source-model>-<source-effort> ->`，第二行右对齐 `<target-model>-<target-effort>`。
- 使用连字符 `-` 连接模型与强度，不使用当前路由显示中的中点 `·`。
- 不改变状态、供应商、路由统计、Token、费用等其他行的语义和颜色所有权。
- 保持 Unicode 显示宽度、极窄终端截断和末尾箭头可见性。
- 旧 Observer 或缺少强度证据的历史记录必须安全降级，不得使快照或列表不可用。

## Acceptance Criteria

- [ ] 非路由、仅强度路由、模型路由分别覆盖格式测试。
- [ ] 路由源行显示请求侧强度，目标行显示最终发往上游的有效强度。
- [ ] 第二行继续按显示宽度右对齐；极窄宽度不会破坏字素或丢失箭头。
- [ ] 实时请求与历史请求使用一致投影和格式。
- [ ] 非 Codex 请求保持现状。

## Open Questions

- 已锁定：旧 Observer 或历史记录缺少可靠强度证据时省略强度后缀，不显示 `-未知`。
- 已锁定：第二行表示配置路由后最终发往上游的有效模型/强度；响应模型映射仍作为不一致证据，不覆盖出站路由显示。
