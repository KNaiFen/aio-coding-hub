# Codex 配置生命周期与 372K 开关设计

## Context

The feature cannot safely be a frontend preset or a second catalog writer. Current config setters can copy projected live bytes into the direct backup, and multiple config/catalog writers lack one transaction boundary. The same files, ownership metadata, rollback, and lifecycle are required to implement the 372K overlay. One task and writer therefore own both the safety foundation and feature.

## State Model

Define three explicit backend states:

1. `CanonicalCodexConfig`: direct user semantics, including legitimate edits and the original catalog pointer/absence.
2. `LiveCodexConfig`: canonical bytes plus active AIO proxy and managed-catalog overlays.
3. `CodexLifecycleManifest`: generation, ownership hashes, active catalog policies, backup references, expected pre-images, and interrupted-transaction phase.

The existing backup/manifest may be extended, but canonical state is never refreshed from already projected live bytes.

## Lifecycle Coordinator

One coordinator owns these semantic operations:

- structured config patch and validated raw TOML replacement;
- Codex MCP-table replacement;
- proxy enable, re-sync, disable, and exit restore;
- managed-profile catalog changes;
- 372K preference enable/disable and catalog rebuild;
- startup recovery.

For every operation:

1. acquire the outer lifecycle lock and reject new work after exit begins;
2. resolve/validate paths once and capture canonical/live/backup/catalog/manifest pre-images;
3. derive next canonical state from canonical bytes;
4. compose any owned catalog and derive the next live projection;
5. journal intended hashes and phase;
6. compare-before-write and atomically replace owned files in documented order;
7. read back bounded ownership/hash evidence and commit/clear the journal.

Before rollback, compare current bytes with this transaction's write. External drift is preserved and surfaced as recovery required.

## Authoritative Toggle Boundary

Persist one backend-owned boolean preference. Expose a dedicated query/mutation accepting only `enabled: bool`; never let the frontend supply slugs, values, paths, or raw JSON. The Codex settings switch reads authoritative state, disables while saving, reuses the serialized mutation/toast path, and never calls refresh/restart/runtime validation.

Preference persistence joins the same transaction as generated catalog, config pointer, and manifest so UI state cannot claim enabled after a partial file operation.

## Complete Base Catalog

Under the coordinator, resolve the canonical original catalog:

1. safe absolute user `model_catalog_json`, when present;
2. otherwise installed Codex executable invoked with separate `debug`, `models`, `--bundled` arguments.

Never inspect or fall back to `models_cache.json`. Bound source/output size, reject unsafe paths/schema, and preserve unknown fields.

## Pure Catalog Composition

Composition is deterministic:

1. complete current base;
2. optional 372K transform of exact slugs `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`;
3. optional managed-profile rows/capabilities;
4. AIO ownership metadata/hash covering base and active policies.

The transform requires exactly one entry per target and changes only `context_window` and `max_context_window` to `372000`. It copies the rest of each object, including `effective_context_window_percent` and auto-compaction fields, without normalization. A structural before/after diff must contain exactly six changed leaf values.

Catalog activation means at least one policy is active: 372K or managed profiles. This replaces the current profile-count-only predicate.

## Enable, Disable, And Restore

Enable composes/writes the owned catalog, projects its absolute `model_catalog_json` pointer, and commits preference/manifest in one transaction.

Disable:

- with profiles: rebuild the same owned catalog from the same canonical base without the 372K transform;
- without profiles: restore the original pointer or remove the AIO-added key, then remove only ownership-verified generated bytes;
- with external drift: preserve external state and return recovery required.

Repeated transitions and restart are idempotent. Proxy off does not disable the preference; live and canonical projections are derived consistently for the active policy.

## Crash Recovery And Exit

The journal distinguishes planned, canonical/backup written, catalog written, live written, and manifest committed phases. Startup repairs or ownership-safely rolls back before proxy startup. Exit closes mutation admission, waits for/acquires the same coordinator, and restores direct live semantics. No recovery path logs raw config/catalog or touches a real user home in tests.

## Runtime Verification Boundary

There is no post-toggle proof step: no catalog refresh, model request, process restart, rescan status, or `372000/372000/95` claim. Tests verify only pure transformation and AIO-owned persisted state. User real-world feedback is external to acceptance.

## Verification Design

- Pure tests: canonical mutation/live projection and exactly-six-leaf catalog diff.
- Temp-home lifecycle tests: structured/raw/MCP/proxy/profile/372K combinations, pointer restoration, cache sentinel, restart, paths, drift, failpoints.
- Barrier tests: each writer vs config/exit without sleep-based ordering.
- Frontend/service/query tests: authoritative toggle, disabled/pending state, error feedback, no `refreshCodex` or model request.
- CI: bindings, frontend unit/typecheck/lint, Rust fmt/Clippy/check/tests, specs/contracts, and platform path coverage.

Locally use only `$gkd-local-verify`; do not run repository-prohibited build/test/generator commands.
