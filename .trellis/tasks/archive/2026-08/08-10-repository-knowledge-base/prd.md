# 整理并建立可持续项目知识库

## Goal

以 `main` 为唯一事实基线，把入口文档、产品与架构说明、运维指南、历史审计、任务计划和执行记录整理成可发现、可追溯、可持续维护的项目知识库，并清理与当前实现不一致的现行说明。

## Requirements

- `main` 是唯一写入目标；`aio-feature-merge` 和 `aio-float-fix` 只用于筛选遗漏资料，禁止整支合并或回灌落后副本。
- 在 `docs/README.md` 建立全局知识入口，并从 `AGENTS.md`、中英文 README 链接；明确现行规范、历史证据、任务记录和会话日志的权威层级。
- 保留标准根入口（README、CHANGELOG、PENDING），把散落的产品基线、审计、过期计划和工程笔记迁入稳定分类目录。
- 历史资料不得伪装为现行指导；保留当时证据，同时增加日期、状态和当前入口说明。
- 修正已确认的文档事实漂移：插件平台兼容性已强制、插件 diagnostics API 已开放、Plugin API v1 说明不绑定不存在的 `0.62.x` 当前版本、本地验证边界与仓库规则一致。
- 补齐 `CHANGELOG.md` 中已发布但缺失的 `0.60.33` 至 `0.60.50`，只根据标签和主线提交记录归纳。
- 将已合并/发布但仍留在活跃目录的 Trellis 任务迁入归档；保留尚未完成真实 OAuth 验证的 Claude OAuth 候选，并从已完成父任务中解耦。
- 修复工作流死链接、工作区索引漂移和文档忽略规则，避免新文档被 `.gitignore` 静默丢弃。
- 不修改产品行为，不把历史路径逐条改写成当前路径，不运行仓库禁止的本地依赖、构建、格式化、测试或原生工具。

## Acceptance Criteria

- [ ] `AGENTS.md`、`README.md`、`README_EN.md` 都能到达 `docs/README.md`，知识入口列出产品、架构、插件、运维、任务与历史资料。
- [ ] 所有纳入范围的项目文档都有明确分类；第三方 checkout、Playwright/设计工具产物和 Trellis runtime state 不进入知识主线。
- [ ] `PRODUCT.md`、健康审计、上游审计、旧插件计划和 `omx_wiki` 资料完成迁移或清理，旧路径不再充当并行事实源。
- [ ] 插件平台、diagnostics 和版本叙述与当前 `0.60.50` 实现一致，文档合同检查同步更新且通过。
- [ ] `CHANGELOG.md` 覆盖 `0.60.33` 至 `0.60.50` 的已发布主线增量。
- [ ] 已交付的 17 个 Trellis 任务归档；活跃列表只保留本任务与仍待真实验证的 Claude OAuth 候选。
- [ ] Markdown 相对链接检查、文档事实检查、云端验证合同自测与 `git diff --check` 通过；未执行的云端质量门被明确列出。
