# TUI 可视性与短时选中态优化

## Goal

改善窄终端中的请求、供应商和状态栏可读性，同时让请求列表在用户停止浏览后自动回到最新记录。

## Requirements

- 请求与供应商视图的综合信息区下方显示暗灰分隔线。
- 请求和供应商初始均无选中项。导航后显示选中态；连续 5 秒无选择操作后必须清空选择和列表偏移，而非仅隐藏高亮。
- 快照刷新不得延长选择期限。详情页期间保留选择，返回列表后重新计时 5 秒。
- 供应商可用、限额、熔断、停用和未知状态必须具有不同且稳定的语义颜色。
- `供`、`路`、`熔`等标签与其状态值分段着色；状态值颜色随状态变化。
- 仅当存在实际 OAuth 标签或额度文本时显示 OAuth 行；无缓存、空额度和 API Key 不占行。
- 交互式状态栏及配置预览左侧预留两列，并采用 Codex CLI 风格的普通青、绿、品红和暗淡分隔符；错误和警告保留红、黄。
- `aio-tui status --once` 的纯文本输出保持不变。
- 不改变 observer 协议、网关、数据库、配置格式或桌面前端。

## Acceptance Criteria

- [ ] 两个列表的标题区和首项之间都有暗灰分隔线。
- [ ] 选择项 5 秒后变为 `None`，列表回到顶部并继续展示最新快照；详情页不因超时关闭。
- [ ] 供应商基础卡片为四行，仅有实际 OAuth 数据时为五行。
- [ ] 可用为绿、限额/冷却/半开为黄、熔断为红、停用/未知为灰。
- [ ] `供/路/熔`标签和值可独立着色，且 `OPEN` 与熔断标签为红色。
- [ ] 状态栏每个可见行左缩进两列，不使用 `Light*` 色或粗体，窄终端中文换行正常。
- [ ] Rust 单元与渲染测试由 GitHub Actions 通过；本机不运行任何 Rust 工具链命令。
- [ ] PR CI 和合并后的 `main` CI 均成功后删除功能分支和临时 worktree。
