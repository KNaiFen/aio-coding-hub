# Codex 上下文压缩标识、用量账本与日志分页

## Goal

识别 Codex 上下文压缩请求并在代理记录中区分本地/远程实现；让用量统计独立于请求明细保留周期；将请求日志改为服务端游标分页。

## Requirements

- 只根据原始客户端请求识别上下文压缩。正文中的
  `client_metadata["x-codex-turn-metadata"]` 优先于兼容请求头；显式元数据不可用时，
  `/responses/compact` 和 `input[].type == "compaction_trigger"` 才作为远程实现兜底。
- 分类器是纯观测功能。未知、损坏、超限或未来格式必须退化为“不标记”或“未知”，不得修改请求、返回错误、改变路由/重试/熔断/超时或记录原始元数据。
- 首页、请求日志页和进行中请求都保留模型名，并显示本地、远程或未知上下文压缩徽标；悬浮信息展示实现、触发方式、原因、阶段和策略。
- 请求日志详情继续受 `request_log_retention_days` 控制；不新增容量预算，不拆分数据库。
- 同一 SQLite 主库新增精简永久用量账本。所有用量、成本、Session、文件夹和供应商限额统计不能因请求明细过期而丢失。
- 账本升级回填不得阻塞网关启动。回填失败时继续使用原日志统计并暂停保留任务；新请求从升级后立即双写。
- 请求日志页使用服务端 keyset 游标分页和服务端过滤。首页现有轻量实时 feed 保持不变。

## Acceptance Criteria

- [ ] 已知 Codex 本地、远程 v1、远程 v2 请求显示正确徽标，未知实现显示“未知”。
- [ ] 任意畸形或未来元数据都不会让请求失败、改变上游字节或影响供应商健康状态。
- [ ] 插件改写不能伪造或覆盖基于原始请求得到的分类。
- [ ] 日志页可按 50/100/200 条分页，支持上一页、下一页、回到最新和现有筛选语义。
- [ ] 游标分页在相同毫秒时间戳下无重复、无漏项，非法游标返回 `SEC_INVALID_INPUT`。
- [ ] v42 数据库可升级至 v43；回填可中断续跑，网关在回填期间仍可启动和转发。
- [ ] 自动保留与手动清理请求日志后，用量、成本和供应商限额统计保持一致。
- [ ] 删除供应商并选择清除用量时，同时删除对应日志和账本；不选择时保留名称快照统计。
- [ ] 生成绑定、前端检查、Rust 测试与 Clippy 全部通过。

## Notes

- HTTP `Content-Encoding` 请求压缩与语义上下文压缩是两个独立功能，不得混淆。
- 手动“清理请求日志”只删除日志与明细，永久账本仅由明确的用量清理语义或应用全量重置删除。
