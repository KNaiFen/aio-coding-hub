# 请求日志筛选分页与时间范围

## Goal

让请求日志页无需手填状态表达式即可定位失败与流内错误，并能通过页码和分钟级时间范围快速定位历史记录。

## Requirements

- 增加“一键查看所有报错请求”的显式选项，不要求用户填写状态码表达式。
- 增加专门的“流内错误”筛选选项；它必须能找到最终 HTTP 状态仍为 2xx 的流内错误。
- 快捷选项与现有 CLI、状态、错误码、方法/路径筛选具有明确、可测试的组合语义。
- 增加可输入、可选择任意页的页码组件，并显示当前筛选结果的总页数；不再只有上一页/下一页。
- 增加可打开的时间筛选，开始/结束精确到本地日期、小时、分钟。
- 提供“最近 1 小时”“今天”“昨天”快捷范围；所有范围统一转换为毫秒级、开始包含/结束不包含的后端边界。
- 应用任一筛选、页大小或时间范围时重置分页位置；历史页继续暂停持久日志自动刷新，活动请求快照照常更新。
- 保持首页实时日志 feed 与历史分页缓存隔离。

## Acceptance Criteria

- [ ] 所有报错快捷选项覆盖已确认的失败集合，不依赖手填状态码。
- [ ] 流内错误筛选以 `attempts_json[*].stream_internal_error` 为可靠事实源，并防御无效/旧 JSON。
- [ ] 页码组件能输入或选择任意有效页，并显示总页数；禁用态、加载态和筛选重置行为正确。
- [ ] 自定义时间、最近 1 小时、今天、昨天按本地时区生成正确的 `[from,to)` 毫秒边界。
- [ ] Rust DTO、SQL、生成绑定、service/query key、hook、reducer/UI 和测试保持一致。
- [ ] 等时间戳游标没有重复或漏项；旧游标兼容策略明确。

## Open Questions

- 已锁定：“所有报错”包含非 2xx HTTP 状态、顶层网关 `error_code` 或流内错误，并排除中断/用户取消。
- 已确认：必须能直接输入或选择任意未访问页，并显示总页数。后端需要为同一筛选会话固定快照水位、返回总数，并支持该快照内的任意页定位。
- 已锁定：时间输入按系统本地时区解释，不额外提供 UTC 模式。
