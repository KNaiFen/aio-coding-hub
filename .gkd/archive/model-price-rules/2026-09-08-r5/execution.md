为指定模型自定义/覆盖价格，或配置模型整体倍率，或只调整输出/缓存读取等分项倍率。费用必须进入 AIO 的真实费用计算。

1. 整体仅指单个模型全部计费项，不存在所有模型共用的默认倍率。

3. 一个表单直接输入，不设置模式切换，不制作多套面板，不自动清空另一组值。
4. 不影响历史费用，不提供自动/手动重算。

- 一个编辑表单包含整体倍率和五类计费项：普通输入、输出、缓存读取、缓存写入 5 分钟、缓存写入 1 小时。每个计费项具有自定义单价和分项倍率输入。
- 单价单位为 USD / 百万 Token。单价与倍率可以同时填写，先确定单价再乘倍率。单价留空表示继承参考价格。
- 全部倍率留空等于 1 倍；仅填整体时所有项使用该倍率；只填分项时未填写项为 1 倍。

- 自定义单价不参与倍率互斥校验。0 和 1 均是已设置，不能用数值真值判断有无输入。
- 显示参考价、自定义值及生效值；未知价格明确为未定价。优先服务、长上下文导致多种参考价格时，不以无条件单一价格误导。
- 加载、读取失败重试、保存中、保存失败和取消状态完整。读取规则失败不能用空配置覆盖；保存失败保留草稿并显示错误。
- 控件与文本适配窗口宽度，不堆叠装饰卡片或引入新视觉系统；不增加解释内部实现的产品文案。

## 定价与持久化

- 新增独立规则文件，位于应用数据 `model-prices/price-rules.json`，采用版本化 DTO 与已有原子 JSON 写入机制。同步和强制同步均不能覆盖此文件。
- 倍率为可选整体字段和可选分项字段，不增加模式字段/枚举。后端在保存边界验证整体和任何分项不可同时存在；前端提供相同即时反馈。
- 在用户输入/IPC 边界验证数值非负、有限且在可表示范围/精度内，拒绝无效值，不静默修正。允许显式 0 单价与 0 倍率，区分空值、0 和未知价。
- 沿用实际计费 CLI/模型，即现有 `effective_cost_basis` 的结果；不得改用原始 requested_model 绕过路由或协议桥接已确定的计费身份。
- 优先匹配实际计费模型的启用自定义规则。没有该规则时，只有基础查价确实经已有别名目标时才采用目标模型自定义规则；同一次计算最多采用一条规则。
- 原模型规则可继承别名目标的参考价格，但不能与目标模型的自定义规则隐式叠加。
- 先解析现有参考价、优先服务、长上下文阶梯、缓存回退和 Token 口径，再仅调整用户填写的项。
- 某项填固定单价时，该项按固定单价计算，不再套用同步价的优先服务或长上下文溢价；该项只填倍率时，倍率作用于该项完整原费用，保留阶梯。
- 已有同步参考价时，覆盖普通输入不能连带改变缓存读取/写入的参考价，各项基于覆盖前的参考价格独立解析。
- 无参考价的新模型必须提供普通输入和输出单价，缓存项可显式覆盖，否则沿用当前从输入价推导缓存价的规则。不能把缺必要价格伪装成免费。
- 各项费用合计后继续乘供应商现有有效倍率，不改变其取值或持久化语义。
- 保持现有定点精度和舍入方式，不在前端重做真实费用计算。无新规则时已有费用结果不变。
- 显式零价/倍率得到可区分的 0；原有未知/无 Token 情况不能因支持零值而一律变为 0。

- 每批读取规则，不增加跨请求规则缓存；原有参考价格缓存保持原职责。
