## 目标

用户可以为指定模型自定义或覆盖价格，也可以设置模型整体倍率或只调整某个计费项，例如缓存读取或输出。设置进入实际费用计算，不能只改变展示。

## 用户已确认的行为

2026-09-08 用户明确：

1. “整体”仅指单个模型的全部计费项，不设置所有模型共用的默认倍率。
2. 模型整体倍率与分项倍率互斥；设置整体后不能同时设置分项，不存在覆盖优先级或二者相乘。
3. 不影响历史费用，不新增自动或手动历史重算。
4. 使用单一表单，不增加模式切换或多套面板；通过校验禁止同一个模型同时填写整体和分项倍率。

新规则只参与后续实时计费。现有同步补齐历史缺失费用继续按原有同步价格和记录中的供应商倍率处理，不读取或套用新增自定义规则；保存本身不触发补齐。

## 拟议交互与行为

以下方案已按用户澄清收敛，并由用户批准执行。

### 设置入口

- 在现有设置的定价区域增加“自定义定价”入口，保留“定价匹配”。复用现有 Dialog、Input、Select、Switch 等组件。
- 规则以 CLI + 完整模型名称精确定位，支持从已有模型建议中选择或输入尚无同步价格的模型；同一键只保留一条规则。
- 每条规则可启用、停用、删除；保存成功后持久化，重新打开可回显。清除自定义值表示恢复继承。
- 编辑区按五类显示：普通输入、输出、缓存读取、缓存写入 5 分钟、缓存写入 1 小时。单价使用 USD / 百万 Token，倍率为独立数值输入。
- 可只填自定义单价，也可只填倍率；允许二者同时存在，此时先确定单价，再应用倍率。各计费项可单独留空，表示继承。
- 同一表单直接显示一个整体倍率输入和五类分项倍率输入，全部可留空，不增加模式控件或独立面板。全部留空等于 1 倍；只填整体时应用于所有项；只填分项时未填写项按 1 倍。
- 检测到整体倍率与任意分项倍率同时有值时，显示“整体倍率与分项倍率不能同时设置”并阻止保存，保留全部输入供用户修改，不自动清空、隐藏或改写另一组值。清空任一侧后解除冲突；自定义单价不参与这项互斥校验。
- 持久化和 IPC 使用可选的整体倍率及可选的各分项倍率字段，不增加模式字段或枚举；后端保存时执行同一互斥校验。有值以是否为空判断，显式 0 和 1 都算已设置，不能使用数值真值判断。
- 显示当前参考价格、自定义值及生效值，明确未定价状态；优先服务和长上下文下不能以一个无条件数字误导用户。
- 表单具备加载、读取失败重试、保存中、保存失败及取消状态；错误发生时保留编辑内容，读取失败时不得以空规则覆盖已有配置。

### 定价优先级

- 自定义规则独立于同步价格保存，同步和强制同步均不得覆盖它。
- 使用已有实际计费 CLI/模型选择规则。先匹配该模型的自定义规则；没有时，仅在现有价格查询确实使用别名目标的情况下使用目标模型规则。同一次计算最多采用一条模型自定义规则。
- 原始模型的分项覆盖可以继承现有别名目标的参考价格，但不能把两条自定义规则隐式叠加。
- 先按当前优先服务、长上下文、Token 口径及缓存回退规则解析参考费用；只调整用户填写的计费项。
- 某项填写固定单价时，该项按固定单价计算，不再额外套用同步价格的优先服务或长上下文溢价；该项只填倍率时，对现有该项完整费用应用倍率，保留原有价格阶梯。
- 有同步参考价格时，只覆盖普通输入不得连带改变缓存读取或写入的参考价格；各项基于覆盖前的参考价格独立解析。
- 新模型没有参考价格时，必须提供普通输入和输出单价；缓存项沿用现有从输入单价推导的规则，也允许显式填写覆盖。
- 各项金额合计后继续叠加现有供应商有效倍率，不改变供应商倍率的保存与取值语义。
- 允许显式 0 单价和 0 倍率；留空、0 和未知价格必须有不同语义。拒绝负值、非有限值和超出可表示精度/范围的输入，不进行静默修正。
- 不配置新规则时，现有计费结果保持一致；费用变化自然反映到已有日志、统计和供应商费用限额中。

### 生效与历史

- 保存不依赖重启；下一批首次终态费用落库使用已保存规则。保存时仍在进行的请求按首次终态落库时规则计算。
- 不增加跨请求规则缓存，以免规则保存后受旧价格缓存影响；基础同步价格缓存仍保持原有职责。
- 保存、修改、停用、删除规则均不写历史请求或统计账本，不触发历史重算、缺失费用补齐或历史查询缓存失效。
- 已完成请求再次收到相同 trace 的持久化更新时，保留此前的费用和供应商倍率，避免新规则通过重放落库改变历史；仍在进行的请求继续允许首次完成计费。以现有终态标记判断，不以费用是否为 NULL 判断。
- `cost_stats` 的历史缺失费用补齐不加载新规则；既有 NULL 仍允许按原有同步机制补齐，已经计算的金额始终保留。通过回归用例证明新增规则不会改变同一历史补齐样本的结果。
- 继续由现有请求落库事务将费用投影到长期账本，不引入历史版本表、规则生效时间线、费用重算命令或后台重算任务。

## 验收标准

1. 用户可创建、编辑、启停、删除指定模型的自定义定价；保存并重新打开后数值和状态一致。
2. 单项价格覆盖实际参与计费；同步及强制同步后覆盖仍存在，清除或停用后恢复参考价格。
3. 同一表单中，只填整体倍率时影响该模型所有计费项；只填输出或缓存读取倍率时仅改变对应项，其余为 1 倍。整体与任意分项同时填写时提示冲突、禁止保存且保留输入；清空任一侧后可保存并准确回显。前后端对显式 0、1 同样判定为已设置，直接提交冲突 IPC 输入也会被拒绝。
4. 用纯合成样例验证：参考单价输入 2、输出 10、缓存读取 0.2 USD / 百万 Token，输出自定义为 8，供应商倍率 0.8。仅填整体 0.5 时，三项生效单价分别为 0.8、3.2、0.08；清空整体并仅填输出倍率 2 时，分别为 1.6、12.8、0.16；所有倍率留空时，分别为 1.6、6.4、0.16。
5. 缓存读取与写入 5m/1h 分别受控；普通输入不重复计算 OpenAI/Gemini 缓存 Token，Claude 的累加口径保持不变。
6. 未修改项的 priority/长上下文价格保持原行为；固定单价覆盖项及倍率项符合约定，倍率不会应用两次。
7. 新模型可通过自定义单价产生费用；缺少必要价格不伪装成免费。显式零价/倍率产生确定的零费用，日志与统计不将其显示为缺失。
8. 使用实际计费模型和 CLI，覆盖模型路由、别名目标和协议桥接情形，不能误用原始请求模型的价格。
9. 保存前已有终态费用在保存、修改、停用、删除规则后保持不变；同 trace 后续写入不得套用新规则改变历史。历史缺失费用补齐结果与未启用新功能时一致。新请求按新规则计费，长期账本与仍存在的详情金额一致；删除旧请求详情不影响统计。
10. 配置读取/保存错误可见；失败不会覆盖旧规则或产生成功反馈。无规则时已有核心计费回归通过。
11. 必要前端与 Rust 自动 CI 通过，绑定无漂移，普通 PR 的 `ci-gate`、`pr-title` 成功；不得以本地静态检查替代。
