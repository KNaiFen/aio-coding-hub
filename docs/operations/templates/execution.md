## 冻结交接与开工核验

本文件和“规划提交”共同构成本次施工入口。执行 session 开始写入前必须确认：

1. 当前目录等于登记 Worktree，当前分支等于登记分支。
2. `BASE_SHA="{{base commit}}"; test "$(git merge-base "$BASE_SHA" HEAD)" = "$BASE_SHA"` 返回成功；有意 rebase 或更换基线时，先由 main 更新计划和登记信息。
3. 本文件所指规划提交存在，且 `prd.md` 的实施授权为“已确认”。
4. 没有未关闭的材料性未决问题；当前唯一写者是本执行 session。

任一项不成立时停止并报告 main；不要依据聊天记录猜测后继续施工。

## 暂停、范围变更与恢复

- 正常施工期间，本执行 session 是该 worktree 的唯一写者。
- 发生阻塞、范围外修改、锁定决定冲突、依赖变化或无法满足 AC 时，即使尚不可验收也要更新 `delivery.md` 为“阻塞”，写明证据、最后安全提交、工作树状态、受影响 AC、待决定事项、决策归属和恢复条件；有可提交改动时提交可恢复检查点，没有可提交改动时如实记录工作树状态，不制造空提交。
- main 确认暂停后才成为临时写者，并在原始计划材料中追加批准的变化、影响的 AC/验证和新的规划提交。执行 session 不改写 main 的原始计划。
- 影响用户行为、兼容性、范围或 AC 的变化必须由用户重新确认。恢复施工前先阅读更新后的计划和 `delivery.md`，再把“当前唯一写者”改回本执行 session。

## 停止并询问 main

出现以下任一情况时不要自行扩大任务：

- 用户锁定决定与当前代码或现行合同冲突。
- 必须修改“允许修改”之外的重要模块或公共接口。
- 发现与其他活动 worktree 的语义冲突或依赖顺序变化。
- 需要破坏兼容性、迁移用户数据、使用真实账号/凭据或执行高风险操作。
- 无法满足某条 AC，或者只能通过明显不同的方案满足。
- CI 失败疑似基础设施或 main 上已有问题，且没有任务内的可靠修法。
