## Register

product

## Users

AIO Coding Hub 面向通过 Codex App、Claude Code、Codex CLI、Gemini CLI、Grok 等桌面端或命令行客户端使用 AI 服务的开发者。用户既可能在本机操作，也可能通过 SSH 远程工作；他们需要在不中断当前开发流程的前提下管理多个上游供应商、观察请求状态并处理供应商差异。

## Product Purpose

AIO Coding Hub 是本地 AI 客户端统一网关。它为不同客户端提供稳定的本机入口，统一处理供应商路由、故障转移、熔断、模型映射、用量统计和请求观测。成功意味着上游变化或故障不会轻易中断开发工作，同时用户能够快速理解当前请求走向、供应商状态、成本和用量。

## Brand Personality

延续现有 AIO 界面的工具属性：克制、紧凑、可靠。桌面端应保持当前组件体系和信息密度；TUI 应保持当前供应商面板的终端原生风格。视觉设计服务于反复操作和快速扫描，不追求重新塑造品牌外观。

## Anti-references

- 不把操作型界面改造成营销页面或展示型仪表盘。
- 不用大面积装饰、巨大留白、夸张动效或不必要的嵌套卡片稀释核心信息。
- 不为了单个新功能重做已经稳定的桌面组件体系。
- 不让 TUI 发明一套与现有供应商面板不同的交互和视觉语言。
- 不让观测、统计或视觉功能改变网关转发、路由和熔断的核心语义。

## Design Principles

1. 转发优先：网关请求链是核心能力，观测与展示必须失败开放。
2. 复用现有语言：优先使用项目已有组件、状态色、间距和交互模式。
3. 紧凑但可扫描：在有限空间内保留高价值信息，并维持清晰分组和稳定尺寸。
4. 跨端语义一致：桌面端和 TUI 对同一状态、统计口径和操作结果给出一致解释。
5. 按需工作：只有用户正在查看或显式触发时才执行可能产生远端请求的辅助功能。

## Accessibility & Inclusion

保留现有键盘操作、焦点状态、浅色/深色主题和减少动效支持。信息密集区域应提供文本明细或悬浮说明。供应商短期可用性状态条在 TUI 中按用户决定仅以颜色区分时间单元，不要求为三种状态使用不同字符；汇总计数和详情仍以文字呈现。
